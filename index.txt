f:T11be,<p>How to serve a static site on a custom subdomain with GitHub Pages.</p>
<h1>1. Static Export</h1>
<p>Your framework must output plain HTML/CSS/JS. No server required.</p>
<p>Next.js:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="js" data-theme="github-dark github-light"><code data-language="js" data-theme="github-dark github-light" style="display: grid;"><span data-line=""><span style="--shiki-dark:#F97583;--shiki-light:#D73A49">const</span><span style="--shiki-dark:#79B8FF;--shiki-light:#005CC5"> nextConfig</span><span style="--shiki-dark:#F97583;--shiki-light:#D73A49"> =</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E"> { output: </span><span style="--shiki-dark:#9ECBFF;--shiki-light:#032F62">"export"</span><span style="--shiki-dark:#E1E4E8;--shiki-light:#24292E"> };</span></span></code></pre></figure>
<p>Angular:</p>
<pre><code>npx ng build --base-href /
</code></pre>
<p>The build output goes to a folder (<code>out/</code>, <code>dist/</code>). That folder is what GitHub Pages serves.</p>
<h1>2. CNAME File</h1>
<p>Put a file named <code>CNAME</code> in your build output root. One line, your subdomain:</p>
<pre><code>sub.domain.com
</code></pre>
<p>GitHub reads this file to know which custom domain belongs to this repo. Without it, GitHub has no way to route <code>sub.domain.com</code> to your repo.</p>
<p>For Next.js, write it into <code>out/</code> after build. For Angular, add it as an asset in <code>angular.json</code> so it copies to <code>dist/</code> automatically.</p>
<h1>3. GitHub Pages Settings</h1>
<p>Settings > Pages > Custom domain > enter your subdomain > Save.</p>
<p>If the CNAME file is already in your gh-pages branch, GitHub fills this in automatically. Either way works.</p>
<p>Wait for GitHub to provision an HTTPS certificate. Takes up to 15 minutes.</p>
<h1>4. DNS Records</h1>
<p>Add a DNS record at your domain registrar (Squarespace, Cloudflare, etc.) pointing your subdomain to GitHub.</p>
<p><strong>Option A: CNAME (recommended)</strong></p>
<p>One record. GitHub changes IP, you don't touch anything.</p>
<pre><code>sub  CNAME  youraccount.github.io
</code></pre>
<p><strong>Option B: A records (alternative)</strong></p>
<p>Four records. Harder to maintain. If GitHub changes IPs, you update manually.</p>
<pre><code>sub  A  185.199.108.153
sub  A  185.199.109.153
sub  A  185.199.110.153
sub  A  185.199.111.153
</code></pre>
<p>For apex domains (<code>domain.com</code>, no subdomain prefix), you must use A records. CNAME on apex breaks other records like MX (email).</p>
<h1>5. How GitHub Routes Multiple Subdomains</h1>
<p>One GitHub Pages server handles all your subdomains. It differentiates by HTTP <code>Host</code> header.</p>
<pre><code>Browser requests sub1.domain.com
  -> DNS resolves to GitHub IP
  -> HTTP header: Host: sub1.domain.com
  -> GitHub finds repo with CNAME file containing "sub1.domain.com"
  -> Serves that repo

Browser requests sub2.domain.com
  -> Same GitHub IP
  -> HTTP header: Host: sub2.domain.com
  -> GitHub finds a different repo
  -> Serves that repo
</code></pre>
<p>Multiple CNAME records can all point to the same <code>youraccount.github.io</code>. The CNAME file inside each repo is what separates them.</p>
<p><code>sub.youraccount.github.io</code> does not work as a direct URL. GitHub Pages only routes by custom domain or <code>youraccount.github.io/repo-name</code>.</p>
<h1>6. DNS Propagation Gotchas</h1>
<p><strong>"DNS check unsuccessful" but the site loads fine?</strong></p>
<p>GitHub's own DNS resolver hasn't refreshed yet. Remove the custom domain, wait a few seconds, re-add it. This forces a fresh lookup.</p>
<p><strong>Site doesn't load, <code>dig sub.domain.com</code> returns nothing?</strong></p>
<p>Your local DNS resolver cached a "not found" (negative cache) from before the record existed. Try querying Google DNS directly:</p>
<pre><code>dig sub.domain.com @8.8.8.8 +short
</code></pre>
<p>If Google returns IPs but your local doesn't, flush your local cache:</p>
<pre><code># macOS
sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder
</code></pre>
<p>Or switch your system DNS to <code>8.8.8.8</code> (Google) or <code>1.1.1.1</code> (Cloudflare). Faster and avoids ISP caching issues.</p>
<p><strong>TLS certificate provisioning messages are normal:</strong></p>
<pre><code>TLS certificate is being provisioned.
This may take up to 15 minutes to complete.
</code></pre>
